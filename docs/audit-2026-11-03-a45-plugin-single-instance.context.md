## Краткий итог

Замок делает то, что обещано: второй запуск на тот же каталог не поднимает
порт, воркер под маркером awf — без сервера, doctor печатает строку.
Проверено на живом процессе: воркер конвейера (pid 2067737,
`AWF_BACKGROUND_CHILD=1`) поднялся в tool-only.

Главное, чего не увидели прошлые стадии — **замок лежит в каталоге, который
awf вычищает своими же руками**: `awf reset --full` и `awf init --force`
удаляют `plugin.lock` у живого владельца, и следующий старт снова становится
владельцем. Дефект A45 возвращается после обычной ремонтной команды.

## Переиспользованные контракты и соглашения

- Чистка `.agentic/state/`: `awf/api/lifecycle.py` — `_clean_state_dir`
  (`lifecycle.py:189`) и набор сохраняемых файлов
  `_PRESERVED_STATE_FILES` (`lifecycle.py:186`). Это готовое правило
  «файл синхронизации не runtime-данные», с обоснованием ровно про
  осиротевший flock.
- Единственная точка bind — `start_http_server` вызывается только из
  `instance.boot` (проверено grep по дереву).
- Один писатель раскладки замка — `instance.py`; `awf/doctor.py` читает
  через `live_owners` (правка архитектора R1).
- Проверка живости pid: `awf/_proc.py:221`, `awf/api/_liveness.py:116`
  (`probe_alive`), теперь ещё `instance.py:167` — три реализации одного
  факта в двух пакетах (направление зависимости plugin → awf запрещено).
