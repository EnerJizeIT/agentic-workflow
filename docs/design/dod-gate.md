# Чек-лист завершения юнита (DoD-гейт)

Что проверяем, кто это меняет и почему проверки дешёвые. Документ отвечает
на вопросы, которые возникают при первом же споре «этот пункт нужен или
нет».

## Зачем

Промт роли не гарантирует, что исполнитель действительно закрыл работу:
пункт «тесты добавлены» может остаться словами в DONE. Чек-лист превращает
условия завершения в список с пробами. Проба — короткая структурная
проверка: файл на месте, строка в файле есть, команда вернула нужный код.
Гейт гоняет пробы и пишет вердикт. Спор «сделано или нет» заменяется
прогоном.

## Владельцы

| Что | Кто меняет | Где лежит |
|---|---|---|
| Базовый набор | супервизор вместе с владельцем | `awf/checklists/base.yaml` |
| Классы проверок | супервизор вместе с владельцем | `awf/checklists/classes.yaml` |
| Волна | супервизор | `.agentic/checklists/waves/<name>.yaml` проекта |
| Блок юнита | композиция при диспатче, руками не правят | `## Чек-лист завершения` в TODO |
| Предложения | исполнитель | секция `## Предложения по чек-листу` в DONE |

Исполнитель не меняет чек-лист. Он может предложить пункт в DONE: гейт
считает такие предложения и печатает `proposals: N`. Супервизор разбирает
их и, если пункт нужен всем, переносит в базовый набор или в класс.

## Правила обновления

Порядок один: инцидент, затем пункт, затем проба.

1. Инцидент: юнит закрыли, а дефект класса «файл потерян», «кодировка
   сломана», «CLI вернул не тот код» всё равно прошёл.
2. Пункт: формулировка, которую можно проверить без человека.
3. Проба: одна из разрешённых (`grep_present`, `grep_absent`,
   `file_exists`, `file_absent`, `json_field`, `command_rc`). Команда —
   только из allowlist, без shell, с таймаутом не больше 120 секунд.
   Нестандартный таймаут переносится в блок юнита
   (`probe(command_rc timeout=30 …)`), иначе после заморозки он бы
   расширился до потолка.

Пункт без пробы в данные не попадает: валидатор отвергает загрузку. Тот же
allowlist повторяется при разборе блока из TODO: гейт исполняет именно блок,
поэтому `bash -c` в ручной правке отвергается на разборе, а не на запуске.

Allowlist — закрытый список флагов, а не список запрещённых. Разрешённое
имя бинаря ничего не гарантирует: `git diff --output=<файл>` пишет в проект,
`rg --pre <команда>` исполняет команду, и в argv при этом нет ни shell, ни
запрещённого имени. Поэтому перечислены все допустимые флаги каждого
бинаря (`grep`, `rg`, `ls`, `test`, `git diff|status|ls-files|show`,
`python3 -m pytest --collect-only`), а позиционный аргумент не может быть
абсолютным путём или содержать `..`. Незнакомый флаг — отказ: у данных при
загрузке, у замороженного блока на разборе, у гейта перед запуском.
Пункт, который нельзя проверить структурно, живёт в приёмке юнита как ручной
(`manual`) — его проверяет принимающий, а не гейт.

Класс не подключается сам. Юнит объявляет его в `checklist_classes:`
контракта. Подсказки по разделу «Границы» печатаются строкой
`checklist_suggested:` — это приглашение, а не слияние; уже объявленный
класс в подсказки не попадает.

Блок фиксируется в TODO при диспатче. Правка волны посреди юнита не меняет
живой юнит. Для уже задиспатченного не начатого юнита есть
`awf checklist apply <todo>`: та же композиция и та же проверка читаемости
блока, бэкап и идемпотентность.
Начатый или архивный юнит не трогаем. Перенесённый TODO (копия при
переплане) приносит свой блок: его не пересобирают, но объявление
проверяют — неизвестный класс, пропавший файл волны или объявленный класс,
чьих пунктов в блоке нет, отказывают диспатчу. Кривой или рукописный блок
на verify — секция `checklist: fail` с причиной, а не падение всего
verify-pack; пункты, которые он всё-таки называет, попадают в `missing`.

Любая правка TODO (полная замена текста, `append`, `section_updates`)
отказывает, если после неё блок не читается или блоков стало два:
незакрытый фенс в теле секции не должен спрятать блок от гейта, а второй
заголовок — заставить гейт проверять один блок, пока человек читает два.

Пункт без пунктов не бывает зелёным. Заголовок блока с пустым телом —
провал `(empty block)`, а не успех: ноль выполненных проверок не закрывает
определение готовности. Это не то же самое, что отсутствие блока у
старого юнита (`checklist: none`).

## Pruning

Список не должен расти вечно. Раз в волну супервизор смотрит на прогоны:

- пункт не падал ни разу за волну и дублирует другой — удалить;
- пункт ловит только свой проект — перенести из базы в класс;
- пункт требует человека — убрать из данных, оставить в приёмке;
- пункт дороже пяти секунд — убрать из гейта, отдать QA.

Удаление пункта — обычная правка YAML. Отдельного флага «выключен» нет:
выключенный пункт копится мусором.

## Метрики

Гейт пишет `CHECKLIST-<todo>.json`, привязанный к отпечатку дерева. Из этих
файлов видно:

- **витки до/после** — сколько ревью-витков понадобилось юниту (сравнение
  волн);
- **catch-rate** — доля юнитов, у которых гейт нашёл пропуск;
- **пересечение с QA** — пункты, которые QA нашёл отдельно: значит проба
  слабая или лишняя;
- **время гейта** — прогон проб на юнит.

Числа считает отдельный этап (TODO-0245), гейт только копит факты.

## Границы

Пробы дешёвые и структурные: они не заменяют тесты и не доказывают
поведение. Тяжёлое — сборка, полный сьют, мутации — остаётся у QA и
verify-pack. Проба не пишет в проект: allowlist разрешает только читающие
команды. Единственное исключение — `python3 -m pytest --collect-only`:
сбор тестов импортирует `conftest` и может оставить служебный кэш pytest.
Окружение пробы чистится от переменных `AWF_*`, путь не выходит за корень
проекта.

Путь пункта — два слоя, как у `command_rc`: загрузка данных отказывает
диспатчу, разбор блока отказывает рукописной строке, а прогон превращает
выход за корень в провал ЭТОГО пункта — остальные проверяются. `grep`
делит коды: 0 — нашёл, 1 — не нашёл, больше — цель не читается; для
`grep_absent` провал, а не «шаблона нет». Чекбокс распознаётся по смыслу,
а не по точному дефису: непонятую строку разбор называет ошибкой, потому
что молча пропущенный пункт — это проверка, которая не выполнялась.

## Где смотреть

- Данные: `awf/checklists/base.yaml`, `awf/checklists/classes.yaml`,
  образец волны `awf/templates/docs/waves/example.yaml`.
- Гейт: `awf/checklist_gate.py` (`run(project, todo_id, tree_sha=...)`).
- CLI: `awf checklist show|check|apply|hash <todo>`.
- Пакет проверки: секция `checklist` в `awf verify-pack`.
- Контракт юнита: `docs/unit-contract.md`, ключи `checklist_classes` и
  `wave`.
