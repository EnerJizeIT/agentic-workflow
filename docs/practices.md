# Практики, рождённые из инцидентов

Здесь лежат практики, которые проект уже enforcement-ит кодом или воротами.
Формат: практика → инцидент → где усилена.

## Канонический полный сьют + флейк-проба

**Практика.** Полный `pytest tests/` — один канонический прогон на attempt,
привязанный к паре (tree-sha, команда): `scripts/suite-canonical.sh`. Артефакт
`.agentic/context/SUITE-<tree-sha>-<cmd8>.json` хранит sha, команду, старт/конец,
код возврата, счётчики и хвост вывода. Пока дерево не изменилось, повторный
вызов отдаёт артефакт и не запускает тесты; перезапуск — только `--force`.
Свои целевые и контрактные прогоны роль делает сама, а `scripts/run-all.sh`
целиком гоняет только при сомнении в воротах. Контрактные тесты в
`awf verify-pack` при этом: тест-подобные команды (`pytest` / `py.test` /
`python -m pytest`, в том числе через `uv run` / `poetry run` / `env` и после
оператора `;`/`&&`/`|`) выполняются дважды — одинаковый исход даёт `flake: ok
(2/2)`, разный — `flake: unstable` и предупреждение в отчёте. Гейт решает
первый прогон: pass → fail остаётся зелёным с предупреждением, fail → pass
остаётся красным (красное не прячется). Тяжёлые ворота (`run-all`,
coverage, mutation smoke, произвольный shell) и timeout прогоняются один
раз; `flake: off` в контракте выключает пробу целиком.

**Инцидент.** В забеге R2 роли запускали полный сьют примерно 66 раз
(около 9 минут на прогон) — это была доминирующая цена каждого витка:
архитектор и аудитор дополнительно гоняли `run-all` целиком. Второй случай —
тайминговый флейк T1b в `tests/negative/test_roadmap_r1_cancel.py`: одиночные
прогоны файла проходили, а в общем прогоне тест падал, и виток ушёл на
разбор нестабильности вместо работы.

**Где усилена.**
- `scripts/suite-canonical.sh` — кэш по tree-sha, `--force`, артефакт с
  фактами.
- `tests/negative/test_miniwave_m1_suite.py` — кэш, смена дерева, флейк-проба.
- `awf/verify_pack.py` (`FLAKE_RUNS`, секция `contract_tests`) — двойной
  прогон и метка `flake`.
- `.agentic/roles/agent-{implementer,architect-review,qa-review,project-auditor}.md`
  — правило «один канонический прогон на attempt»; в репозитории его несут
  tracked-шаблоны `templates/roles/` и `awf/templates/roles/` (для свежего
  клона и для установки из wheel), `.agentic/roles/` — materialized-копия.
- `tests/unit/test_template_sync.py` — обе деревни шаблонов и живой
  `scripts/suite-canonical.sh` не расходятся с тем, что получает новый проект.
