# Слой 11 — рекомендации по рефакторингу

**Роль:** ведущий разработчик. Оценены размер функций, смешение ответственности, дублирование правил и расхождение между API, CLI и MCP. Это предложения по упрощению реализации после фиксации поведения; сами по себе размеры файлов не считаются дефектами.

## Карта сложности

Самые крупные продуктивные модули: `tools/awf.py` — 2319 строк, `awf/api/pipeline.py` — 1783, `awf/metrics.py` — 1673, `awf/pipeline_engine.py` — 1247. AST-подсчёт показывает 553 строки у [`_build_parser`](../../awf/cli.py#L106), 365 у [`execute_agent_stage`](../../awf/pipeline_engine.py#L883), 317 у [`dispatch_todo`](../../awf/api/dispatch.py#L58), 301 у [`continue_pipeline`](../../awf/api/pipeline.py#L1010) и 287 у [`run_next`](../../awf/api/run.py#L467). Длина полезна как указатель для чтения; приоритет ниже основан на реальных расхождениях поведения из послойного аудита.

## R-01 · Единое владение исполнением проекта · высокий приоритет

[`start_pipeline`](../../awf/api/pipeline.py#L832) проверяет PID отдельно от запуска; [`run_start`](../../awf/api/run.py#L198) проверяет состояние забега отдельно от записи. Вынести переходы в один сервис исполнения с проектной lease/lock и идентификатором поколения забега: `reserve → spawn/execute → release`. Foreground, background, `continue` и `run_next` должны проходить одну и ту же точку владения. PID оставить индикатором процесса, а не источником права запуска. Изменение закрывает **A-02/A-13** и уменьшает число независимых проверок живости.

**Безопасный порядок:** сперва сформулировать инвариант «один владелец проекта и элемента очереди», затем внедрить его на публичных входах, после этого удалять прежние частные guards. Проверять отказ и освобождение резервации на каждом выходе.

## R-02 · Один слой хранения TODO и архива · высокий приоритет

[`dispatch_todo`](../../awf/api/dispatch.py#L58), [`init_project`](../../awf/api/lifecycle.py#L50), [`restore_todo`](../../awf/api/lifecycle.py#L372) и [`archive_todo`](../../awf/todos.py#L98) по отдельности решают, какие пути существуют и когда их можно заменить. Выделить операции `reserve_id`, `archive`, `restore` и `reset_runtime` в общий слой хранения с проверкой **всех** пространств имён (`inbox`, `done`, сигналы) до изменения файлов. Сделать режим удаления архива явным аргументом отдельной операции, а обычный `init` идемпотентным. Это адресует **A-11/A-12** и упрощает дальнейший разбор частично выполненных переходов.

## R-03 · Коммит как проверяемый объект результата · высокий приоритет

Сейчас `approve` пишет verdict и сигнал отдельно, `_handle_next` игнорирует булев отказ commit gate, а commit gate сам выбирает файлы через глобальный Git index. Заменить разрозненные `bool` и файлы сигналов на явный `CommitPlan`: TODO ID, поколение, проверенный отпечаток, список файлов и ожидаемый verdict. Создавать коммит через изолированный index; результат возвращать как `committed/skipped/refused/error` с причиной и обрабатывать одинаково на execute и verify стадиях. Это связывает **A-01/A-04/A-14/A-15**. Начинать с результата и инвариантов, затем заменять механизм staging: такая последовательность снижает риск сменить поведение сразу в нескольких местах.

## R-04 · Разделить получение формы и применение изменений · средний приоритет

[`do_POST`](../../agent_workflow_ui/src/agent_workflow_ui/http_endpoint.py#L138) за 161 строку проверяет HTTP, разбирает тело, сохраняет payload, меняет статус и запускает materialization. Выделить `parse/validate submission`, устойчивую запись, применение и запись итога как отдельные шаги. Реестр форм должен различать `received`, `applied`, `failed`, а MCP `read_submit` возвращать итог применения. Это даёт единое место для повторной обработки сохранённого payload и исправляет **A-05**. В [`tools/awf.py`](../../agent_workflow_ui/src/agent_workflow_ui/tools/awf.py#L38) использовать общий async адаптер для блокирующих API вызовов; сейчас прямой синхронный `dispatch_todo` в async wrapper способен ждать baseline до 300 секунд (**A-20**).

## R-05 · Разделить сбор метрик, расчёт и вывод · средний приоритет

[`collect_metrics`](../../awf/metrics.py#L1410) в 251 строке одновременно читает конфигурацию, SQLite, Git, каталог цен, считает окна, строит таблицы и пишет отчёт. Разделить на вводные структуры `SessionFacts`, `CommitFacts`, `PriceCatalog`, чистый расчёт `MetricsSnapshot` и отдельно рендер/запись. Парсер TODO ID и собственных commit subject должен быть общим для метрик и публичных API. Такой разрез прямо предотвращает повторение **A-10/A-17** и позволяет проверять расчёт на данных в памяти без базы и Git.

## R-06 · Единый реестр MCP инструментов и контрактов · обычный приоритет

[`create_server`](../../agent_workflow_ui/src/agent_workflow_ui/server.py#L9) вручную регистрирует 47 tools, а [`tools/awf.py`](../../agent_workflow_ui/src/agent_workflow_ui/tools/awf.py#L1) содержит 2319 строк обёрток с несколькими стилями вызова (`_exec`, `to_thread`, прямой API вызов). Сохранить индивидуальные сигнатуры и docstrings tools, но вынести регистрационный список и метаданные в один проверяемый источник для сервера и документации. Одновременно привести обёртки к общему правилу вызова синхронных API. Это снижает расхождение **A-08/A-20** без генерации непрозрачных универсальных tools.

## R-07 · Убрать второй парсер `.include` · обычный приоритет

[`run_next`](../../awf/api/run.py#L642) сам читает `BASELINE-<id>.include`, хотя [`read_include_list`](../../awf/include_untracked.py#L51) уже реализует это и не вызывается. Выбрать одно место чтения формата; затем удалить неиспользуемый код или заменить ручной блок вызовом helper. Это локальный шаг с малым радиусом изменения и первый кандидат для уборки из [слоя 10](10-dead-code.md).

## Порядок внедрения

Сначала зафиксировать инварианты данных и запуска (**R-01–R-03**), затем поток формы и асинхронный MCP вызов (**R-04**), после них разрезать аналитический модуль (**R-05**) и очистить регистры/дублирование (**R-06–R-07**). Для каждого шага сохранять внешний CLI/MCP контракт и отдельно проверять сценарии из соответствующего дефектного пункта. В рамках аудита рефакторинг не выполнялся.
