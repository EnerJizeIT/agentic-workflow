# Слой 7 — метрики и привязка к TODO

**Роль:** аналитик данных. Просмотрены выбор сессий из SQLite, разделение проектов, связь worker/commit с TODO, окна забега и расчёт строк кода. База пользователя не открывалась; выводы основаны на коде и тестовых сценариях.

## A-10 · P2 · TODO после 9999 теряются или связываются с неверным номером

Публичные API принимают `TODO-\d{4,}`, а автоматическая нумерация после `TODO-9999` даст `TODO-10000`. Метрики используют [регулярное выражение с ровно четырьмя цифрами](../../awf/metrics.py#L114) для заголовка worker сессии; такая сессия не попадёт в worker totals. Другое выражение ([строка 115](../../awf/metrics.py#L115)) ищет четыре цифры без правой границы в commit subject: `TODO-10000` превращается в `TODO-1000`. В результате часть затрат исчезает, а часть строк кода относится к неверному юниту.

**Рекомендация:** общий парсер TODO ID с `\d{4,}` и явной границей конца номера. **Проверка после исправления:** отдельные записи `TODO-1000` и `TODO-10000` имеют независимые worker сессии, коммиты и строки кода.

## A-17 · P2 · Метрики видят только коммиты стадии `verify`

[`collect_commit_info`](../../awf/metrics.py#L467) берёт коммит лишь если тема содержит `verify`. Но `on_approved: commit_and_next` и `commit_and_report` допустимы и на execute стадии, где [commit gate](../../awf/commit_gate.py#L247) формирует тему `awf(<имя стадии>): TODO-<id>`. Если пользователь настроил коммит до verify, метрики пропускают этот коммит: [`collect_code_lines`](../../awf/metrics.py#L617) не считает его строки, а [`build_windows`](../../awf/metrics.py#L486) не использует его время как конец окна. Когда worker сессий также нет, TODO вообще пропадает из итогового набора ([сборка](../../awf/metrics.py#L1522)).

**Рекомендация:** распознавать собственный формат `awf(<stage>): TODO-<id>` независимо от имени стадии; отделять commit metadata от правил построения окна. **Проверка после исправления:** execute коммит без verify коммита отображается с корректными строками и окном.
