# Слой 13 — совместимость установленных пакетов

**Роль:** инженер выпуска и совместимости. Собраны оба wheel из текущего дерева (`pip wheel --no-deps --no-build-isolation`), затем они установлены вместе с зависимостями в отдельные окружения Python 3.10.21, 3.11.16 и 3.12.3. Все проверки выполнялись из каталога без исходных пакетов в `sys.path`; путь импортированного модуля сверялся с `site-packages` окружения. Конфигурация и файлы запуска плагина направлены в изолированные XDG каталоги внутри временной папки.

## Матрица smoke-проверок

| Проверка установленного wheel | Python 3.10 | Python 3.11 | Python 3.12 |
|---|---:|---:|---:|
| Установка `awf` и `agent-workflow-ui` с зависимостями | прошла | прошла | прошла |
| Импорт обоих пакетов именно из `site-packages` | прошёл | прошёл | прошёл |
| `awf --help` | прошёл | прошёл | прошёл |
| `create_server()` и список 47 MCP tools | прошли | прошли | прошли |
| Данные ядра, оба файла скиллов, три стандартных HTML шаблона | найдены / рендерятся | найдены / рендерятся | найдены / рендерятся |
| `agent-workflow-ui` запускает локальный HTTP/MCP сервер и выходит после закрытия stdin | прошёл | прошёл | прошёл |

Для Python 3.12 отдельно проверен `python -m awf --help`. Стандартный `python3 -m venv` на машине не создал окружение из-за отсутствия `ensurepip`; применён `uv venv`. Это ограничение хоста, а не ошибка wheel. Временные окружения и XDG данные остались в рабочем каталоге: автоматический контроль отклонил команду их очистки.

## Оценка и рекомендации

**Новых ошибок упаковки в проверенной матрице не обнаружено.** Ранее отмеченный **A-18** остаётся пробелом CI: workflow [собирает и проверяет содержимое обоих wheel](../../.github/workflows/ci.yml#L57), но [smoke-устанавливает только ядро](../../.github/workflows/ci.yml#L71). Ручной успешный запуск текущей сборки не защитит следующий релиз от пропавшего шаблона, entry point или сломанной регистрации tools.

**Рекомендация:** в package job установить **оба** собранных wheel в одно чистое окружение и выполнить импорт из `site-packages`, `awf --help`, `create_server().list_tools()`, рендер стандартных шаблонов и запуск entry point плагина с изолированным XDG. Добавить хотя бы Python 3.10 и 3.12 к package smoke, поскольку `requires-python` заявляет `>=3.10`.

## Наблюдение о времени старта

При первом smoke с обычным `PATH` плагин не достиг сообщения о запуске HTTP сервера за 8 секунд. В [`__main__.py`](../../agent_workflow_ui/src/agent_workflow_ui/__main__.py#L44) список моделей вычисляется до запуска сервера, а [`read_available_models`](../../agent_workflow_ui/src/agent_workflow_ui/opencode_config.py#L165) может ждать `opencode models` до 10 секунд. При изолированном `PATH` без внешнего `opencode` entry point запустился примерно за 1–2 секунды на всех трёх версиях. Это наблюдение о готовности сервера, а не установленный дефект wheel; полезно перенести сбор моделей за границу готовности MCP/HTTP или выполнять его лениво.

## Предел проверки

Проверены запуск и ключевые packaged assets, а не полный MCP диалог с клиентом и не весь test suite на каждой версии. Зависимости были разрешены в их доступных на дату проверки версиях; будущие комбинации транзитивных зависимостей не охвачены.
