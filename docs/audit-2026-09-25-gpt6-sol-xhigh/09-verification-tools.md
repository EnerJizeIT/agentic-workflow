# Слой 9 — вспомогательные инструменты проверки

**Роль:** инженер проверочных инструментов. Просмотрены `prove_red`, `mutations`, `verify_pack`, их CLI обёртки и соответствующие тесты. Этот слой отделяет проверки самого пайплайна от инструментов, которыми доказывают качество результата.

## A-19 · P2 · Путь теста при `prove-red` может выйти за пределы worktree

[`prove_red`](../../awf/prove_red.py#L103) берёт список тестов из аргумента или блока `prove_red` в TODO-контракте. В [`_copy_test_files`](../../awf/prove_red.py#L305) до копирования проверяются только непустота строки и отсутствие NUL. Выражения `project_dir / rel` и `worktree / rel` допускают `..`, абсолютный путь и переход через символьную ссылку. Для относительного пути с `..` файл, существующий вне проекта, может быть прочитан, а `shutil.copy2` может записать за пределами временного worktree. Это происходит до запуска pytest. В тестах `test_prove_red.py` есть штатные и ошибочные сценарии, но проверки границы пути нет.

**Рекомендация:** требовать относительный путь к файлу внутри проекта; для источника и назначения проверять результат `resolve()` на принадлежность соответствующему корню. Для назначения отдельно учитывать символьные ссылки в baseline worktree. Отклонять путь до создания или заполнения worktree, если проверку можно провести заранее.

**Проверка после исправления:** `../`, абсолютный путь и символьная ссылка наружу завершаются управляемой ошибкой; файлы вне проекта и временного worktree не изменяются.

## Остальные наблюдения

`prove_red` удаляет временный worktree в `finally`; `mutations` отказывается запускаться на грязном Git-дереве и восстанавливает исходное содержимое файла в `finally`. `verify_pack` собирает отдельные секции результата и ограничивает время внешних команд. Эти свойства просмотрены статически, без запуска команд на рабочем дереве.

## Ограничение

Риск `A-19` следует из операций с путями. Реальный сценарий записи вне worktree в ходе аудита не воспроизводился, чтобы не создавать побочных файлов.
