# Слой 2 — жизненный цикл TODO и состояние забега

**Роль:** инженер целостности данных. Просмотрены `init`, `dispatch`, `restore`, `archive`, `reset`, гигиена TODO, очередь забега и файловое состояние. Приоритеты оценивают последствия, а не частоту использования.

## A-11 · P1 · Повторный `awf init` удаляет runtime и архив

При существующей `.agentic/` вызов `init_project(..., force=False)` переходит в [_clean_runtime](../../awf/api/lifecycle.py#L100). Список удаления включает `inbox`, `outbox`, `handoff`, **`done`**, `state`, `logs` и другие каталоги ([строки 31–45](../../awf/api/lifecycle.py#L31)). Это поведение намеренно закреплено тестом, но обычный CLI затем пишет «Created .agentic/ skeleton», а MCP вызов выполняется без дополнительного барьера. Состояние живого забега и весь архив могут быть уничтожены одним повторным вызовом `awf_init`; проверки живого процесса перед удалением нет.

**Рекомендация:** сделать обычный `init` безопасным повторным вызовом; очистку runtime вынести в явно названную операцию с перечислением удаляемого. До любой очистки проверять живой pipeline. Если совместимость не позволяет изменить семантику сразу, возвращать явное предупреждение и список данных до действия, а не после него.

**Проверка после исправления:** повторный init на проекте с активным TODO и архивом не меняет файлы; отдельная операция очистки выполняет заявленный режим.

## A-12 · P1 · Повторный ID может перезаписать текущий TODO и историю

`dispatch_todo` резервирует ID только по отсутствию файла в `inbox` ([строка 189](../../awf/api/dispatch.py#L189)); для явного `todo_id` наличие `done/<id>/` не проверяется. После завершения `archive_todo` переносит новый `TODO.md`, `DONE.md` и `PROGRESS.md` в тот же каталог через `shutil.move` ([строки 119 и 139](../../awf/todos.py#L119)). На POSIX существующие файлы назначения могут быть заменены. Отдельно `restore_todo` переносит архивный `TODO.md` в `inbox/<id>.md` без проверки, занят ли адрес ([строка 394](../../awf/api/lifecycle.py#L394)).

**Сценарии:** явная повторная выдача архивного ID и последующее завершение стирают прежние артефакты архива; восстановление при уже созданном TODO с тем же ID стирает текущий текст задачи. Тесты подтверждают идемпотентность повторного `archive_todo` без новых файлов, но не защищают эти коллизии.

**Рекомендация:** отказ при занятом ID в любом из `inbox`/`done` для обычной выдачи; восстановление только в свободный путь; архивирование в существующий каталог с версиями или отказом на конфликт. Перемещения выполнять после общей проверки всех адресов.

**Проверка после исправления:** конфликтный `dispatch`, `restore` и повторное архивирование оставляют обе версии байт в байт неизменными либо сохраняют обе версии под разными именами.

## A-13 · P2 · Проверка активного забега отделена от записи

В `run_start` активность читается до блокировки ([строка 222](../../awf/api/run.py#L222)); затем `write_run` под lock без условной проверки заменяет поля ([строка 233](../../awf/api/run.py#L233)). Два одновременных вызова с `force=False` могут оба пройти guard, а последний перезапишет очередь первого. В `run_next` индекс снимается до запуска пайплайна, а финальный mutator проверяет только `active`, после чего записывает ранее вычисленный `index + 1` ([строки 702–714](../../awf/api/run.py#L702)). Если состояние забега изменилось в окне запуска, проверка владения текущим элементом отсутствует.

**Рекомендация:** условный переход `inactive → active` внутри одного `update_run`; для `run_next` добавить поколение/ID забега и compare-and-swap по индексу и элементу очереди. Держать резервацию элемента до окончания запуска и явно восстанавливать её при отказе.

**Проверка после исправления:** параллельные `run_start` дают один успешный старт; параллельные `run_next` запускают один элемент ровно один раз.

## Положительные свойства

`dispatch_todo` использует `O_EXCL` для атомарной резервации свободного файла; `run_state.update_run` защищает обычные read-modify-write операции lock; `retire_todo` уже использует уникальные имена для ряда артефактов. Эти механизмы полезно распространить на всю цепочку владения TODO.

## Ограничение

Первоначально гонки были выведены из порядка операций; позже параллельный `run_start` и файловые последствия `init`/`restore` воспроизведены в [слое 12](12-recovery-reliability.md). `A-11` является задокументированным поведением, которое оценивается здесь как опасный публичный контракт, а не как случайная ошибка реализации.
