# Слой 5 — локальные HTTP границы

**Роль:** инженер безопасности и устойчивости. Просмотрены checkpoint сервер, сервер отправки MCP форм, dashboard HTTP, обработка Origin, длина тела и формирование HTML.

## A-03 · P1 · Решение checkpoint не привязано к открытой форме

POST обработчик checkpoint принимает `decision=approve|edit|reject` без токена формы или идентификатора конкретного открытия ([код](../../awf/plan_checkpoint.py#L592)). `Origin: null` и отсутствие Origin допускаются ([проверка](../../awf/plan_checkpoint.py#L538)), так как форма открывается из `file://`; это не удостоверяет инициатора. Порт публикуется в состоянии и журнале ([запись](../../awf/plan_checkpoint.py#L410)). Любой локальный клиент, получивший порт, может первым отправить решение, которое по правилу first-wins определит дальнейший ход пайплайна. Обработчик также не ограничивает путь POST адресом `/checkpoint`.

**Рекомендация:** криптостойкий одноразовый токен на открытие формы, проверка токена и пути под тем же lock, которым фиксируется решение; аннулировать токен после первого принятого POST. Origin оставить дополнительной проверкой.

**Проверка после исправления:** запросы без токена, с чужим токеном и на другой путь не меняют holder/файл решения; правильный повторный POST не меняет первое решение.

## A-07 · P2 · HTTP обработчики допускают длительное зависание на теле запроса

Checkpoint преобразует `Content-Length` без обработки неверного числа или ограничения размера и вызывает `rfile.read(length)` ([строка 604](../../awf/plan_checkpoint.py#L604)). Неверный заголовок вызывает исключение в потоке; большой или медленно отправляемый запрос может удерживать поток и память. В сервере MCP форм есть лимит 1 MiB, но при превышении лимита обработчик **сначала вычитывает заявленное тело целиком** ([цикл](../../agent_workflow_ui/src/agent_workflow_ui/http_endpoint.py#L194)); частичная отправка с большим `Content-Length` также удерживает поток. Оба сервера используют `ThreadingHTTPServer` без явного ограничения одновременных запросов.

**Рекомендация:** возвращать 400/413 сразу после проверки заголовка, ограничить время чтения и число активных обработчиков; для допустимого тела принимать только заданный объём. Закрытие соединения с oversized запросом лучше бесконечного drain.

**Проверка после исправления:** неверная, отрицательная, чрезмерная и неполная длина завершается ограниченно по времени, без фиксации решения или submit.

## Что защищено сейчас

Оба сервера слушают `127.0.0.1`; dashboard не отдаёт wildcard CORS; checkpoint экранирует текст TODO при построении HTML; Jinja шаблоны MCP работают с `autoescape=True`. Эти меры проверялись по коду, но не устраняют указанные границы авторизации и чтения.

## Ограничение

Браузерная воспроизводимость атаки через стороннюю страницу не проверялась. Вывод A-03 касается факта отсутствия привязки решения к форме и возможности произвольного локального POST на открытый порт.
