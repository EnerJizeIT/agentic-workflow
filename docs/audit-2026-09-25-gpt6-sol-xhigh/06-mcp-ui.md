# Слой 6 — MCP и пользовательские формы

**Роль:** инженер интерфейса и сценариев пользователя. Просмотрены регистрация tools, создание/отправка/чтение форм, хранение статуса, материализация команды проекта, обработка ролей и JS шаблоны.

## A-05 · P2 · Статус «отправлено» предшествует применению формы

HTTP submit сохраняет payload, затем вызывает [`finalize_submit`](../../agent_workflow_ui/src/agent_workflow_ui/http_endpoint.py#L254), а только после этого `process_role_saves` и `process_role_deletions`. Ошибка `apply_project_setup` в [`process_role_saves`](../../agent_workflow_ui/src/agent_workflow_ui/roles_processor.py#L185) лишь записывается в лог. Ответ браузеру остаётся 200 и «Форма отправлена», а повторная отправка уже обработанной формы не запускает материализацию снова. Аналогичный порядок у `increment-planning`: ошибка `apply_increment_plan` логируется после terminal статуса ([обработчик](../../agent_workflow_ui/src/agent_workflow_ui/http_endpoint.py#L272)).

**Последствие:** пользователь и агент видят успешную отправку, хотя `pipeline.yaml`, настройки ролей или `plan.md` не обновились. **Рекомендация:** отделить `received` от `applied/failed`, сохранять результат применения и ошибки, вернуть его через `read_submit`; повторять применение из сохранённого payload идемпотентно. Многосоставную запись либо выполнять транзакционно, либо явно показывать частичный результат.

**Проверка после исправления:** имитация отказа записи pipeline/config/plan показывает ошибку в форме и MCP ответе; повтор из сохранённого payload завершает настройку ровно один раз.

## A-16 · P2 · Данные моделей и скиллов попадают в `innerHTML` без экранирования

В шаблоне project-setup [`modelOptions` и `agentOptions`](../../agent_workflow_ui/src/agent_workflow_ui/render/default_templates/project-setup.html.j2#L468) собирают HTML конкатенацией строк с названиями моделей, ролей и скиллов. Готовая строка присваивается `tr.innerHTML` ([строка 565](../../agent_workflow_ui/src/agent_workflow_ui/render/default_templates/project-setup.html.j2#L565)). При выборе скилла его `title` и полный `content` снова вставляются через `cell.innerHTML` ([строки 606–611](../../agent_workflow_ui/src/agent_workflow_ui/render/default_templates/project-setup.html.j2#L606)); замена только `"` на `&quot;` не экранирует `<`, `>`, `&`. Источник названия и текста — локальный [`SKILL.md`](../../agent_workflow_ui/src/agent_workflow_ui/opencode_config.py#L329). Jinja `tojson` безопасно встраивает начальные данные в JavaScript, но последующая сборка DOM снова трактует их как HTML.

**Последствие:** импортированный или сгенерированный скилл с HTML способен исполнить скрипт в открытой локальной форме. То же возможно для отображаемого имени модели/роли. **Рекомендация:** создавать `option`, `input` и `span` через DOM API, назначая `textContent` и `value`; не строить HTML из внешних строк.

**Проверка после исправления:** строки с HTML тегами и кавычками отображаются как текст в списке и карточке; DOM не получает новых узлов из данных скилла.

## A-20 · P2 · Часть `async` MCP инструментов блокирует цикл событий

Общий адаптер [`_exec`](../../agent_workflow_ui/src/agent_workflow_ui/tools/awf.py#L38) отправляет синхронные API вызовы в `asyncio.to_thread`, но ряд инструментов вызывает их прямо из `async def`. Так, [`awf_dispatch_todo`](../../agent_workflow_ui/src/agent_workflow_ui/tools/awf.py#L1502) синхронно исполняет `api.dispatch_todo`, который вызывает `create_baseline`. Последний запускает настроенную проверку с тайм-аутом до **300 секунд** ([код](../../awf/api/pipeline.py#L629)) и затем собирает сведения об окружении. Прямые вызовы есть также у `awf_init`, `awf_rollback`, `awf_approve` и других обёрток. Пока идёт такой вызов, остальные задачи того же MCP event loop не получают управление; тайм-аут транспорта или зависание соседних tools возможны даже при исправной проверке baseline.

**Рекомендация:** для всех синхронных API операций использовать один адаптер с `asyncio.to_thread`, сохранив индивидуальную обработку результатов после `await`. Для долгой операции рассмотреть отдельное задание со статусом, если транспортный лимит короче её допустимого времени.

**Проверка после исправления:** при медленном `baseline_cmd` другой лёгкий MCP вызов на том же сервере отвечает до завершения dispatch; ошибки и `next_action` сохраняют прежний контракт.

## Положительные свойства

Идентификатор формы проверяется перед построением пути; запись submit YAML атомарна; статус формы меняется под lock; шаблоны рендерятся с Jinja autoescape; список имён шаблонов ограничен. Сильные локальные меры не заменяют явный результат применения и безопасную сборку динамического DOM.

## Ограничение

Для A-05/A-16/A-20 выполнен статический анализ пути данных и вызовов event loop. Браузерный proof of concept и адресное воспроизведение этих дефектов не запускались; установленный MCP сервер отдельно проверен в [слое 13](13-installed-packages.md).
