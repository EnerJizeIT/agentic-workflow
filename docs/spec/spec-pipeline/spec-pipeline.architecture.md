## 2. K1 — Шапка и матрица как данные

Шапка — строки `Ключ: значение` в начале файла до первого заголовка `## `; порядок строк не важен:

```
Статус: DRAFT | REVIEW | BLOCKED      (авторские)
Статус: PASS | FAIL                   (ревью требований)
Статус: READY | BLOCKED               (готовность)
Ревизия: <слаг>-<номер>
Входы: <файл>@<ревизия>, ...
База кода: commit <sha>
Проверено: <файл>=<ревизия>, ...      (вердикт и готовность)
Пакет-sha: <hex>                      (только готовность)
```

`parse_spec_header(text, role)` возвращает значения и номер строки; роль и набор статусов — по имени файла. Обязательны `Статус`, `Ревизия`, `Входы`, `База кода`; `Проверено` — для вердикта и готовности, `Пакет-sha` — для готовности. Нет ключа, пусто или слово вне набора — ошибка с файлом и ключом (`AC30`); опечатка статуса не равна `DRAFT`.

AC30 читается как четыре обязательных ключа; поля «назначение» нет (FR5 принят).

Матрица — единственная обязательная таблица пакета (`AC31`), только в готовности; четыре колонки, пары цепочки — в ячейке:

```
## Матрица покрытия

| ID | Источник | Сценарий/контракт | Проверка |
|---|---|---|---|
| R3 | spec-pipeline.md#R3 | C1/C3/K2/K3/D2 | T5/T6/IMP2/IMP3 |
| INV2 | spec-pipeline.md#Не должно измениться | ветка:совместимость/K4/D6 | метод: pytest tests/negative/test_miniwave_m5_sourceref.py |
```

Заголовок точный. `ID` — `R#`/`AC#`/`INV#` один раз. `Источник` — `<путь>#<секция>`, путь от каталога пакета, заголовок существует и уникален, пояснений нет. `Сценарий/контракт` — токены через `/`: `C<цифры>`, `K<цифры>`, `D<цифры>`, `план`, `ветка:<текст>` или метка; номера проверяются на существование, цепочку читает ревью. `Проверка` — `T#`/`IMP#` через `/` (минимум один `T#`) либо `метод: <текст>`. Дубль, ID без строки, строка без источника, несуществующая секция или токен — «не готов» (`AC13`). Цепочка `ID → С#/K#/D# → T#/IMP#` влезает в колонки; AC13/AC31 не меняются (FR2).

Отпечаток — пять документов: контекст, требования, ревью, архитектура, тест-спека (готовность исключена; RR27). Путь — от каталога пакета, `/`, без `./` и `..`; порядок — по байтам пути в UTF-8; префикс — `путь`, `0x00`, строчный hex sha256 сырых байтов, `0x0a` на каждый файл; `Пакет-sha` — sha256 префикса. Байты не нормализуются (CRLF, BOM). Вектор T4: `a.md`=`x\n`, `b/c.md`=`y\n` → `820b644ee4afc011044b1a82207471464d13cfd240a0d610d3580eec1a643766`. База — префикс от 7; базы шести и готовности совпадают.

## 3. K2 — Предикат готовности

```
spec_gate(project_dir, package_dir) -> SpecGate
SpecGate: ok: bool, reason: str, details: list[str]
```

Проверки по порядку, без языковой модели; первая неудача даёт `reason`, остальные — строки `details`. Тот же вердикт печатает `awf spec-check` (`AC4`):

1. шесть файлов на месте; лишние — только в `assets/` (`AC21`);
2. каждая шапка разбирается (K1);
3. авторские документы не в `DRAFT` и не в `BLOCKED`; `REVIEW` не блокирует (`AC5`);
4. ревью требований — `PASS`;
5. его `Проверено` покрывает текущую ревизию требований;
6. готовность — `READY`, её `Проверено` покрывает ревизии шести документов;
7. базы всех документов совпадают;
8. `Пакет-sha` совпадает с отпечатком пяти документов (`AC6`);
9. матрица полна (K1);
10. бюджеты в норме (K6).

Отпечаток ловит правку без смены ревизии; ревизии — для сообщения. Устаревание даёт один из трёх детерминированных текстов (`AC8`): ревизия («готовность называет req-3, документ на req-4»), база (обе), байты («sha a → b»); повтор тот же.

При `BLOCKED` сообщение берёт вопрос и владельца из первого ряда `## Открытые вопросы` (`ID | Вопрос | Владелец | Влияние`) заблокированного документа; нет раздела или строк — отказ называет это отдельно (`AC8`, `AC29`).

Тесты: T5 (создание), T6 (старт/продолжение), T15 (сквозной).

## 5. K4 — Передача нормы

```yaml
spec_package: docs/spec/spec-pipeline
source_refs:
  - docs/spec/spec-pipeline/spec-pipeline.md#R3 — Гейт готовности
  - docs/spec/spec-pipeline/spec-pipeline.test-spec.md#T4 — Отказ при REVIEW
```

- `spec_package` — каталог внутри проекта; без `source_refs` (минимум одна) юнит не создаётся (`AC9`).
- Ссылка: внутри пакета, точный уникальный заголовок, тело до следующего заголовка того же или выше уровня, **минимум одна непустая строка** (`AC12`); пустое тело — отказ с локатором.
- Покрытые ID — строки матрицы с этим «Источником», минимум один (`AC11`); тело — текст, не источник ID.
- Абсолютный путь, `..`, путь вне пакета — отказ с локатором; `source_ref` без пакета сохраняет INV2, при пакете проверяется по K4.
- В TODO: `## Пакет спецификации` (путь, `Пакет-sha`, ревизии шести, все ID, риски из `## Остаточные риски`; нет раздела — «не заявлены»), затем `## Первоисточник (<секция>)` на каждую ссылку в объявленном порядке. Пересказ нормы запрещён (R6).
- `spec_package` и `source_refs` добавляются в `_CONTRACT_KEYS` и в `docs/unit-contract.md`. Отказы — до побочных эффектов, с локатором (`AC12`).

## 6. K5 — Границы записи стадии

Стадия объявляет `output` (один артефакт; свежесть проверяется) и `write_allow` — пути проекта. Загрузчик (`ALLOWED_STAGE_KEYS`, `Stage`) требует: внутри проекта и каталога своего `output`, не в `.agentic/` и `.git/`. Allowlist = `output` ∪ `write_allow`.

Движок снимает манифест дерева до и после стадии: путь → sha256 изменённых отслеживаемых и новых неигнорируемых файлов, удалённый — маркер; разница даёт тронутые пути. Игнорируемое (`.agentic/outbox`, PROGRESS, DONE) не входит.

Путь вне allowlist: движок пишет `.agentic/context/STAGE-DIFF-<todo>-<stage>.md` и переводит стадию в `BLOCKED` (`DONE` перекрывается), коммита нет, откат запрещён (доктрина 02, `AC15`, `AC16`). Запись не предотвратить: `bash` доступен, права в `awf/_env.py` — по имени инструмента; обещание — «названо и не в коммите».

`files` dev-юнита — отдельный механизм: отчёт и находка verify, не запрет коммита и не источник allowlist (`AC17`); описывается в `docs/unit-contract.md`.

`AC7` — тем же механизмом: готовность в allowlist только финальной стадии, ранний `READY` даёт `BLOCKED`; правку вне пайплайна механизм не ловит, и это названо.

## 7. K6 — Бюджет объёма

Счётчик — `awk '{n += NF}'` по файлу целиком, включая заголовки и таблицы (RR24). Пороги: документ — 2200, пакет — 11000; ключи `spec.budget.document` и `spec.budget.package` в `.agentic/config.yaml`, без ключа — значения по умолчанию. Превышение — MAJOR с числом и порогом (`AC19`); вердикт даёт `spec_gate` (пункт 10), таблицу «документ — слова — порог» печатает `awf verify-pack` (`spec-budget`). Матрица (~44 строки) входит в бюджет готовности.

Дубли и лишние документы (`AC20`, `AC21`) проверяет ревьюер: машинное «это повтор» без модели ненадёжно и в итерацию не входит.

## 8. K7 — Композиция `spec` и цикл FAIL

Шаблон `awf/templates/pipelines/spec.yaml` регистрируется в `BUILTIN_PIPELINES` как `spec`; локальный `.agentic/pipelines/spec.yaml` приводится к нему. Шесть авторских стадий получают `output` и `write_allow`; verify остаётся без `output` (`AC3`, `AC18`).

Цикл FAIL — без нового кода: у `spec-requirements-review` политика `on_rejected: rollback_to:spec-requirements`; `REVIEW-REJECTED` даёт rollback и replan — супервизор выпускает TODO следующей ревизии (находки, тот же `pipeline: spec`). Бюджет — `max_rollbacks` (3); исчерпан — стоп. `BLOCKED` готовности — не цикл: пакет читается как `BLOCKED`, вход в разработку отклоняется с вопросом и владельцем.

Инструкция супервизору «после FAIL создать ревизию» живёт в локальном файле роли супервизора (`.agentic/roles/supervisor.md`, не коммитится) и машинно не проверяется (A2).

## 9. Состояния

| Объект | Переход | Событие | Наблюдаемый результат |
|---|---|---|---|
| Документ | `DRAFT` → `REVIEW` | автор закончил | файл и шапка |
| Документ | `REVIEW` → принят | вердикт с этой ревизией в `Проверено` | строка вердикта |
| Документ | принят → `REVIEW` | новая ревизия | отказ гейта с двумя ревизиями |
| Пакет | `REVIEW` → `READY` | готовность с отпечатком | `spec_gate.ok` |
| Пакет | `READY` → устарел | другие байты покрытого документа | отказ с двумя sha |
| Пакет | любой → `BLOCKED` | вердикт или стадия | отказ с вопросом и владельцем |
| Стадия spec | идёт → `BLOCKED` | путь вне allowlist | `STAGE-DIFF`, нет коммита |

Недопустимы: автор объявляет `PASS`/`READY`; готовность без `PASS`; `READY` без покрытия ревизий — каждый даёт отказ или `BLOCKED`.

## 10. Совместимость и отказы

- Нет `spec_package` — обычный пайплайн (R8, INV1).
- INV2: извлечение секции не меняется (точный заголовок, тело, проза, код-фенсы, отказ до эффектов). Новые отказы — только в пути пакета; `source_ref` без пакета сохраняет `_раздел пуст_`.
- Правка покрытого документа во время dev-юнита работу не отменяет: норма вставлена снимком (D6); verify готовность не перепроверяет (FR3).
- `.agentic/` не коммитится (INV4); вердикты и статусы живут в документах пакета и переносятся git.
- `reqrev-4` — PASS в форме K1 (FR1 закрыт); `readiness-2` перевыпускает готовность по K1 и пересчитывает `Пакет-sha` (A3).
- Не делаем: `Spec-ref` в коммите, лимит символов на тело секции, машинную сверку «файл → ID» (`AC14`), автодетект дублей.

## 11. Решения

| ID | Решение | Альтернатива и почему нет |
|---|---|---|
| D1 | Статус автора — в шапке, принятость — в `Проверено`; `REVIEW` не блокирует | `.agentic/state/` не переживает git; `PASS` у автора ломает границу ролей |
| D2 | Один предикат, три точки вызова | Копия проверки в каждой точке расходится |
| D3 | Ссылки + снимок; норма в одном месте | Секция-копия нарушает R6; собранный документ — второй артефакт синхронизации |
| D4 | Граница стадии — манифест и отсутствие коммита | Запись не предотвратить: `bash`, права по имени инструмента |
| D5 | Устаревание по содержимому, ревизии — для сообщения | Только mtime даёт ложные срабатывания; только ревизия пропускает правку без бампа |
| D6 | Коммит не перепроверяет готовность | Перепроверка убивает готовую работу из-за чужой правки |
| D7 | Имена `spec_gate`/`spec_package` | `unit_readiness` занят смыслом «юнит не начат» |
| D8 | Покрытые ID — строки матрицы с точным источником | Поиск ID в теле зависит от разметки и даёт пустой список |
| D9 | Allowlist стадии и `files` юнита — разные механизмы | Сведение в один даёт `BLOCKED` вместо находки или наоборот |
| D10 | Счётчик бюджета — `awk NF` | Второй счётчик делает вердикт зависимым от инструмента |
| D11 | FAIL — `rollback_to` + replan супервизора | Новый сигнал требует правок движка и семантики |
| D12 | Композиция — шаблон + регистрация варианта | Только локальный `.agentic/` не переживает чистый клон (A6) |
