## 2. Как собирается контекст

`awf/agent_stage.py::run_agent_stage` (~стр. 253): `build_prompt(kind, todo_id, project_dir)` → блок задания (959 символов) → идентичность стадии (~300) → `--file` роли целиком → `--file` доктрины (2 958) → `--file` TODO → `--file` по одному handoff-у на каждую предыдущую агентскую стадию → `--model` роли → `--session` для ролей из `ALLOWED_ROLES`.

Детали:

- `awf/pipeline.py::_compute_kind`: индекс 0 → `plan`, последний → `verify`, середина → `execute`. Ключи `action:`/`kind:` отвергаются.
- Ветка `plan` — инструкция супервизора: 4 000 символов README «Project vision», «создай TODO-NNNN», без контракта DONE.
- Контракт сигнала DONE/BLOCKED есть только в ветке `execute`.
- Доктрина склеивается из трёх файлов без отбора по роли.
- `resolve_prev_handoffs` (стр. 732) берёт все предыдущие стадии, кроме supervisor, по одному файлу на стадию: имя по стадии, запасное — по роли. У стадий `checklist-close` и `checklist-check` своего файла нет, запасное правило отдаёт файлы implementer и QA — те же, что уже переданы. Дедупликации нет.
- `opencode run` стартует в каталоге сессии (`/home/pklochkov`), флага `--dir` нет.
- Reuse сессии разрешён трём ролям: implementer, refactoring-specialist, qa-review.
