### A. Тип и состав блоков

**T1 — таблица семейств полна.** AC1; `FAMILIES`: пять семейств, шесть строк; `reviewer/checklist` — строка `reviewer`; нет `AUDIT`/`METRICS`; ID из словаря; `STAGE` первый, `OUTPUT` последний.

**T2 — один носитель типа.** AC16; `resolve_stage_type` (K1). Конфиг `{stage_types: {"agent-impl": "execute"}}`; `unknown-stage`, пустой конфиг, `reviewer2`, второе поле-уточнение → `StageTypeUndeclared` с именем и путём; роль не влияет.

**T3 — одна роль, два типа.** AC1, AC21. `agent-project-auditor` в `default` — `execute`, в spec — `spec`: наборы по §5 разные; роль одна.

**T4 — spec на нулевой позиции.** AC21, AC22. `spec-context` — индекс 0, конфиг `spec`: `engine_kind = execute`, набор `spec`, DONE/BLOCKED/REVIEW в тексте, нет «создай TODO», путь output назван.

**T5 — контракт вывода.** AC22. Фразы — литералами в тесте, не импортом `OUTPUT`; все четыре есть, `OUTPUT` последний.

**T6 — новый тип данными.** AC2. Ключ `audit` с `[STAGE, UNIT, CRIT, OUTPUT]` и роль в `tmp_path`: сборки успешны, неизвестный тип — отказ.

**T7 — противоречие владельцев.** AC8. TODO `status: done` против DONE.json `blocked`; GATES PASS против `gates: ["failed"]`. Одна строка `CTX-CONFLICT` на пару, сборка успешна, секции пересказа нет.

**T8 — схема пайплайна.** AC15, INV4. 12 файлов грузятся без правок; `action:`/`kind:` — ошибка с именем поля; состав и порядок стадий прежние.
