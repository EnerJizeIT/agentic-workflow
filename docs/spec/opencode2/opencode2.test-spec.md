## Проверки

### T1 — argv на v1 и v2, отсутствие ключа
- Покрывает: R1, AC1, AC2, AC11, INV1; K2; C1.
- Уровень/вход: unit `resolve_standalone` + integration через фейковый `opencode`; перехват `run_subprocess_until_signal` у воркера и супервизора.
- Данные: фейк 1.19.4 с `auto`, без ключа, `off`; фейк 2.1.4 с `auto` и без ключа.
- Ожидания: 1.19.4 — argv побайтно прежний, `--standalone` нет; 2.1.4 — `["opencode","run","--standalone","--auto",…]`, прочие аргументы и порядок прежние; оба спавна строят argv одним helper'ом; ключа нет — режим `auto`.
- Ловит: флаг на v1 (мёртвый старт), потерянный флаг на v2, переставленные аргументы.

### T2 — Домен ключа из реального YAML
- Покрывает: R1, AC5, AC37; K2; C1.
- Уровень/вход: unit `awf/config.py::load` + `resolve_standalone`; файл `.agentic/config.yaml` на `tmp_path`, не python-dict.
- Данные: `standalone: on`, `off`, `auto`, `"true"`, `"False"`, `maybe`, `1`, `[1]`; ключа нет.
- Ожидания: `on/off/true/false` после `safe_load` дают режимы on/off; `auto` — auto; ключа нет — auto; `maybe`, число, список — отказ с текстом `opencode.standalone` и значением, до спавна (фейк не вызван).
- Ловит: разбор до YAML (строка `on` принята за bool), тихий откат в `auto` на мусоре.

### T3 — `on` на 1.x и неизвестная версия
- Покрывает: R1, R2, AC3, AC10, AC39, INV1; K2, K3; C1, C2.
- Уровень/вход: integration, фейк 1.19.4 с `on`; unit `probe_version` с мусорным выводом и `on`.
- Данные: (а) 1.19.4 + `on`; (б) версия unknown + `on`; (в) 2.1.4 + `off`.
- Ожидания: (а) флага нет, предупреждение называет `--standalone` и версию, стадия стартует и доходит до сигнала; (б) флага нет, затем типизированный отказ K3 про неизвестную версию; (в) флага нет, отказ по R2.
- Ловит: мёртвый старт 1.x с флагом (CTX12), «on + unknown» с флагом (RR35).

### T4 — Проба версии, двойники, таймаут
- Покрывает: R1, AC4, AC6, AC7, AC38; K1; C1.
- Уровень/вход: unit `probe_version`; шим `tests/infra/opencode_shim/opencode`, стаб `tests/stubs/opencode`.
- Данные: пустой вывод, `мусор`, rc 1, отсутствующий бинарь, `sleep 6` на `--version`; шим и стаб с `AWF_SHIM_VERSION=2.1.4`.
- Ожидания: пустой/мусор/rc — `unknown`, без исключения; нет бинаря — `missing`; таймаут срабатывает за ≤7 с, `unknown`, старт не висит; шим и стаб печатают версию, rc 0, сигналов не пишут, `invocation.log` не меняют; `--version` вызван один раз на процесс, background-ребёнок считает отдельно.
- Ловит: исключение вместо `unknown`, зависание на молчащем бинаре, ложный DONE от стаба (CTX2).

### T5 — Отказ start на 2.x без изоляции

- Уровень/вход: integration `start_pipeline` foreground/background с фейком 2.1.4.
- Данные: `auto` и `off`.
- Ожидания: `auto` — `run_mode` старта, флаг в argv; `off` — `StartResult.run_mode="noop"`, текст содержит `opencode.standalone`, код 0, не «неизвестная ошибка»; нет `awf-launch.lease`, TODO-ID не израсходован, baseline и `state/` не созданы.
- Ловит: отказ после lease, общий текст ошибки вместо причины.

### T6 — Четыре входа: тот же отказ без следов
- Покрывает: R2, AC13; K3; C2.

- Ожидания: формы отказа `StartResult`, `RunNextResult(action="refused")`, `RunStartResult(active=False)`, `ServiceRunResult(action="refused")`; текст один и тот же; хеши каталогов совпадают, `git status --porcelain` пуст, TODO не зарезервирован, lease не взят, фейк не вызван.

### T7 — Managed — предупреждение вместо отказа

- Уровень/вход: integration `start_pipeline`, `awf doctor`; env `AWF_OPENCODE_MANAGED`.

- Ожидания: opt-in — отказа нет, флага нет, предупреждение в выводе и строка doctor `managed: on — worker env может игнорироваться, standalone выключен`; env перекрывает файл; без opt-in — `false` и отказ T5.
- Ловит: managed не отличается от обычного проекта, ложное включение по реестру сервиса.
