# Требования: awf 3.0 — только opencode 2.x

Статус: REVIEW
Ревизия: req-4
Входы: opencode2-only.context.md@ctx-1; opencode2-only.requirements-review.md@reqrev-3; opencode2-only.readiness.md@ready-2
База кода: commit 0384ba35ffc97ce370e6dc94bee098277d775860
Основание: TODO-0315; решение владельца 31.10.2026 («awf 3.0 работает только на opencode ≥ 2»); CTX1–CTX13.

## Изменения

req-4 (находки ready-2): INV7 согласован с AC19; `provider` добавлен в V1-ключи R5; AC19 ссылается на арх. D5; R1 называет отсутствующую в коде ветку отказа на major < 2.

## Цель и scope

awf — внутренний инструмент, обязательств перед opencode 1.x нет. Переходный слой 2.3.0 (выбор режима по версии, две схемы базы, две формы конфига) убирается целиком.

Владелец awf запускает пайплайн, читает `awf doctor` и метрики. В итерации R1–R12; вне — миграция `opencode.db`, удаление истории, новые возможности, изменение managed-режима. IMP-юнитов не больше шести: код, тесты, verify, миграция конфига владельца, релиз 3.0.0.

## Текущее поведение и ограничения

- Режим выбирается по версии: `awf/opencode_version.py:150-232`; вызовы — `awf/agent_stage.py:250-258`, `awf/supervisor.py:1199-1208`; preflight — `awf/api/pipeline.py:1922-1945`, `awf/api/run.py:401-413`.
- Две схемы базы и две формы конфига: `awf/metrics.py` (`V1`/`BOTH`), `awf/opencode_db.py:36-68`, `awf/session_store.py:48,246-260` (`session` первой), `awf/_net.py:172-212`, `awf/_env.py:265-294,371-446`, `awf/opencode_agents.py:63-160`, `awf/doctor.py:293-325`.
- Конфиг ищет `awf/xdg.py:31-33`; `awf init` правит файл агентов после подтверждения. V1-ключи нормализуются в памяти без перезаписи файла (CTX3); двойники отвечают `1.19.4` (CTX1); пакет 2.3.0.

## Требования

### R1 — Отказ на opencode < 2 и на неизвестной версии

MUST. В итерации. C1. TODO п.1; CTX1; D1, D2.

Перед первым побочным эффектом любого входа (`start`, `continue`, `run-next`, `run-service-start`, foreground, background, MCP) awf читает `opencode --version` и требует major ≥ 2. Ветки «major < 2 → отказ» в коде нет — она добавляется (CTX1). Major < 2 — отказ «awf 3 требует opencode 2.x» с найденной версией и rc 1; нет бинаря — «opencode не найден», rc 1; версия не определена (пусто, мусор, rc≠0, таймаут) — отдельный текст и rc 0 (D1). Отказ одинаков для всех входов, включая managed, и стоит до TODO, baseline, `.ready`, `current`, dispatch, lease, PID.

AC1 — сид (1,19,4): каждый вход отказывает, текст содержит «требует opencode 2.x» и «1.19.4».
AC2 — версия не определена: отказ с отдельным текстом и rc 0, без исключения.
AC3 — следов нет: `.agentic/*` не изменились, дерево чистое, TODO-ID цел, lease не взят, стадия не спавнилась.
AC4 — managed при 1.19.4 — тот же отказ (D2); сид (2,2,3) — старт идёт.
AC5 — `--version` один раз на процесс.

### R2 — `--standalone` передаётся всегда, ключ `opencode.standalone` удалён

MUST. В итерации. C2. TODO п.1; CTX9; D3; RR11.

Флаг стоит в argv обоих спавнов и `opencode models` при любом конфиге. Ключ не читается: домена `auto/on/off`, отказа на небулево и предупреждения про 1.x больше нет. Managed (INV3) — исключение: флага нет, предупреждение прежнее.

AC6 — `--standalone` в argv обоих спавнов и `opencode models` при отсутствии ключа и при `auto`, `on`, `off`, `maybe`, `true`; прочие флаги и порядок прежние.
AC7 — `standalone: maybe` больше не отказ: старт идёт, флаг передан.
AC8 — `awf doctor` печатает WARN про неизвестный ключ и файл не меняет.

### R3 — База: только схема V2

MUST. В итерации. C3. TODO п.2; CTX4, CTX5, CTX12; A2, D5.

Единственная читаемая схема — `session_v2` + `session_message`. Чтение `session`, `part`, `message`, «both» и «v2 в форме v1» удаляется у метрик, recent models (`awf/api/model_check.py`, плагин) и захвата сессии. V1-схема, пустая база или база без таблиц — `n/a` с причиной; захват молча не пишет id. На смешанной базе захват читает `session_v2`; v1-тесты удаляются.

AC9 — синтетическая V2-база: те же числа и формат, что на текущем v2-пути.
AC10 — V1-база, пустая база и база без таблиц: `n/a` с причиной, rc 0; захват id не пишет, ошибки нет.
AC11 — смешанная база: захват берёт `session_v2`, метрики считают только V2.
AC12 — recent models у CLI и плагина из одного источника V2; на V1 предупреждение «моделей не найдено», не падение.
AC13 — в `awf/` нет чтения `session`/`part`/`message` по SQL и именам таблиц (шаблоны — R10).

### R4 — baseURL: только форма V2

MUST. В итерации. C4. TODO п.3; CTX8.

Preflight читает только `providers.<p>.settings.baseURL`; `provider.<p>.options.baseURL` и приоритет «v1 первым» удаляются. Ни одной формы — preflight выключен, сообщение прежнее.

AC14 — только V2-форма: URL найден, запрос `{base}/models` прежний; только V1-форма — preflight выключен, файл не изменён.
AC15 — обе формы: побеждает V2.

### R5 — Env воркера и файл агентов в форме V2

MUST. В итерации. C4. TODO п.3; CTX2, CTX8; D1, D3 (арх.); RR1, RR2.

`awf/_env.py` собирает `OPENCODE_CONFIG_CONTENT` в форме V2: `agents`, `mcp.servers`, `permissions` — упорядоченный список правил. Правила стадии и `locked_deny` идут последними: побеждает последнее совпадение. Имена инструментов — 2.x (`bash`→`shell`, `write`→`edit`, маппинг — арх. D2).

Файл агентов: `awf init` правит лишь отсутствующий или уже V2-файл — после подтверждения, существующий бэкапит. Файл с V1-ключами (`provider`, `agent`, `permission`, `mcp.<имя>`) остаётся байт-в-байт с WARN «сконвертируй по R11».

AC16 — верхнеуровневые ключи env: нет `agent`, `permission`, `mcp.<имя>`; есть `agents`, `mcp.servers`, `permissions`.
AC17 — профиль стадии запрещает инструмент, разрешённый хостом: правило стадии последнее, проба `opencode run` 2.2.3 показывает отказ (арх. D1).
AC18 — `locked_deny` остаётся запретом при любом хостовом правиле.
AC19 — `awf init` без файла: пишет V2-форму, бэкапа нет (нечего терять, арх. D5), doctor молчит; на V2-файле: дописывает недостающее, бэкап до записи, doctor молчит.
AC20 — файл с V1-ключами: байты до и после совпадают, WARN «сконвертируй по R11», ключи не выдумываются, падения нет.

## Сценарии

### C1 — Запуск на неподдерживаемой версии

Владелец, чистое дерево.

1. `awf start` при 1.19.4 → отказ «awf 3 требует opencode 2.x» (AC1); версия не читается → отказ fail-closed (AC2); managed → тот же отказ (AC4); `--version` один раз на процесс (AC5).
2. `continue`, `run-next`, `run-service-start` → тот же отказ, следов нет (AC3).
3. Ставит 2.2.3 и повторяет `awf start` → старт идёт (AC4).
Результат: на 1.x пайплайн не начинается и не оставляет файлов.

### C2 — Флаг и удалённый ключ

1. Конфиг без ключа → флаг в argv обоих спавнов и `opencode models` (AC6).
2. `off` → флаг передан; `maybe` → старт идёт (AC6, AC7).
3. Managed → флага нет, предупреждение прежнее (AC8).
Результат: режим не выбирается, исключение — managed.

### C3 — Метрики и захват сессии

1. V2-база → прежние числа (AC9).
2. V1-база и пустая база → `n/a` с причиной, rc 0; захват id не пишет (AC10).
3. Смешанная база, reuse → строка `session_v2` (AC11).
4. Recent models у CLI, doctor и плагина — из V2 (AC12, AC13).
Результат: v1-история не читается, и об этом сказано.

### C4 — Конфиг: baseURL, env, файл агентов

1. Только V2-форма baseURL → URL найден; только V1 → preflight выключен; обе → побеждает V2 (AC14, AC15).
2. Env V2 (AC16); запрет стадии сильнее хоста (AC17); `locked_deny` сильнее любого правила (AC18).
3. `awf init` без файла → V2-форма без бэкапа; на V2-файле — бэкап (AC19); файл с V1-ключами → байты целы, WARN (AC20).
Результат: одна форма на запись и на чтение.

### C5 — `awf doctor`

1. V2-конфиг → ok; V1-конфиг → WARN «сконвертируй», хеш не изменился (AC21).
2. Строк режима нет (AC22); `opencode.standalone` в конфиге awf не блокирует запуск (AC23).
Результат: doctor объясняет, что делать, и не правит.

### C6 — Сеть

1. Смерть на мёртвом эндпоинте 2.2.3 → класс network (AC24).
2. Удалённая 1.x-строка → не network; `auth`, `transient` прежние (AC25).
Результат: классы не сместились.

### C7 — Инженерные проверки: чистка, доки, версия, страж

1. Поиск шаблонов R8 в `awf/` → ноль (AC26); state-store и commit-пути целы (AC27).
2. Доки, карта, `docs/design.md`, пометка пакета → только 2.x (AC28–AC30); версия 3.0.0 (AC37, AC38).
3. Страж зелёный после IMP4 (AC31); каждый шаблон в копии модуля делает его красным (AC32); легальные имена не ловятся (AC33).
Результат: возврат 1.x ловится тестом, релиз отличим.

### C8 — Миграция конфига владельца

1. Бэкап `opencode_config_file()`, хеш зафиксирован (AC34).
2. Правка на V2, проверка `opencode debug config` и `awf doctor` (AC35).
3. Jira и Confluence отвечают (AC36); провал → откат из бэкапа.
Результат: конфиг в V2, инструменты работают, откат возможен.

## Не должно измениться

INV1 — guard `proc.pid > 1` и tripwire `_forbid_session_kill` не тронуты (grep, тесты).

INV2 — отказ до побочных эффектов, перечень мест — R1 (AC3).

INV3 — managed остаётся opt-in и не передаёт `--standalone` (AC8).

INV4 — модели ролей (`models.<role>.model`) и `argv_agent_flag` не меняются (тесты).

INV5 — классы `network/auth/transient` сохраняют смысл, меняется лишь набор строк (AC25).

INV6 — формат `.agentic/state|inbox|outbox` и сигналы DONE/BLOCKED прежние (e2e).

INV7 — чтение не пишет конфиг opencode; запись — только `awf init`, с бэкапом, если файл существовал (AC19–AC21).

INV8 — пустая или чужая база даёт `n/a` с причиной, не нули (AC10).

INV9 — lease: второй запуск — noop с текстом (тесты).

## Что ломается для пользователя 1.x

- Пайплайн не запускается: отказ старта и есть ответ (R1).
- `opencode.standalone` не действует: флаг передаётся всегда (R2).
- Метрики по v1-сессиям не читаются: `n/a` (R3); потерю данных владелец принял.
- V1-форма конфига не читается: нужен ручной перевод (R11); `awf init` V1-файл не правит и предупреждает (R5).
