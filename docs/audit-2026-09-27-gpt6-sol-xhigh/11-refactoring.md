# 11 — Переработка и границы ответственности

**Роль:** ведущий разработчик. **Проверка:** R-01…R-07 исходного аудита по фактическому коду.

| Пункт | Фактическое состояние |
|---|---|
| R-01, единый владелец запуска | Lease + CAS реализованы и тестируются, но право старта, позиция очереди, сигнал и процесс всё ещё отдельные переходы; V-01/V-02 показывают остаток. Частично. |
| R-02, единое хранение TODO | Коллизии защищены, общий слой всех `dispatch/archive/restore/init` не выделен; файлы и частичные ошибки остаются. Частично. |
| R-03, `CommitPlan` и типизированный исход | `awf/commit_plan.py` и изолированный index реально работают; fingerprint необязателен, отдельного worktree нет. Предметно выполнен, целевая граница частична. |
| R-04, получение/применение формы | Статусы `received/applied/failed` и повтор есть; HTTP обработчик остаётся большим и совмещает несколько шагов. Поведение исправлено, разрез частичен. |
| R-05, расчёт метрик отдельно от I/O | Общий ID парсер есть; `metrics.py` всё ещё совмещает сбор, расчёт и рендер. Частично. |
| R-06, единый реестр MCP | `registry.TOOLS` — единый источник регистрации; 47 tools сверяются тестом. Выполнен. |
| R-07, один `.include` парсер | `run_next` использует `read_include_list`. Выполнен. |

Размеры ориентиры, не дефекты сами по себе: `api/pipeline.py` — 1909 строк, `metrics.py` — 1701, MCP `tools/awf.py` — 2306, `plan_checkpoint.py` — 1055. Ближайшая полезная переработка — единый результат запуска с откатом всех побочных эффектов и техническое ограничение approval; механическое дробление файлов до этого даст мало пользы.

**Вывод:** заявление старой дорожной карты «R-01…R-07 закрыты» точно для части функциональных исправлений, но не для всех структурных целей.
