**Дата:** 27.09.2026. **Версия:** `v1.4.0`, `main` / `f030458` до записи этого отчёта. **Автор проверки:** GPT-6 Sol XHigh. **Область:** проект `agentic-workflow`, включая пакет `agent_workflow_ui`. Исходный аудит 25.09 изучен до удаления устаревшей папки; при необходимости он доступен в истории Git на `f030458`. Текущие выводы находятся здесь.

## Вердикт

Исходные 21 сценарий A-01…A-21 имеют адресные регрессионные тесты; полный набор проекта зелёный. Программа исправлений реально изменила границы данных, запуска, Git, HTTP, форм и упаковки. Утверждение «весь контур закрыт» сейчас слишком сильное: при повторной проверке воспроизведены два отказных пути `run_next`, а гарантии независимого supervisor в значительной мере остаются инструкциями для модели.

| ID | Приоритет | Текущий вывод | Где доказательство |
|---|---|---|---|
| V-01 | P1 для foreground API | `run_next(background=False)` с результатом `foreground`, `exit_code=1` возвращает `started` и сдвигает индекс очереди; MCP wrapper вызывает background путь. | [12 — восстановление](12-recovery-reliability.md) |
| V-02 | P2 | Исключение `start_pipeline` оставляет `.ready` и резервацию `current`; повтор требует ручного разбора состояния. | [12 — восстановление](12-recovery-reliability.md) |
| V-03 | P1 для гарантии независимой приёмки | Все 47 MCP tools регистрируются для одного сервера, `awf_approve` не получает идентичность роли, а произвольная строка `evidence` и пустой `verified_sha` создают разрешающий сигнал. | [16 — supervisor](16-supervisor.md) |
| V-04 | P2 | `readonly_roles` не запрещает запись: список по умолчанию пуст; при настроенной роли сохраняются пользовательские `edit/write=allow` и всегда разрешённый `bash`. | [16 — supervisor](16-supervisor.md) |
| V-05 | P2 | Контракт TODO, `prove_red` и факты DONE остаются необязательными; mutation smoke не включён в текущий CI. | [14 — стратегия](14-strategy.md) |

Риски V-03/V-04 оцениваются относительно заявленной цели: отделить исполнителя от независимого решения о приёмке. Это проверка границы полномочий внутри awf, а не утверждение о злонамеренном внешнем пользователе.

Контроль — сьют 3105 passed, gates 5/5, CI зелёный; выпуск — 1.5.0 в git (PyPI ждёт токен). Открытое: мультимодельный А/Б/В-эксперимент владельца.

## Что проверено фактически

- `bash scripts/run-all.sh`: 5 ворот зелёные; 2824 теста прошли, Ruff прошёл, 8 предупреждений `DeprecationWarning` от `fork()` в многопоточном процессе.
- Адресно: 31 тест на A-02/A-11/A-12/A-13/A-21 прошёл.
- `bash scripts/wheel-smoke.sh`: оба wheel установлены в отдельный venv; CLI, импорт, 47 MCP tools, шаблон формы и entry point прошли.
- `bash scripts/mutation-smoke.sh`: 4/4 мутации пойманы. `--report`: 13/13 пойманы. Оба запуска сделаны на чистом отслеживаемом дереве, скрипт восстановил исходники.
- Два отказных пути `run_next`, наследование прав `readonly_roles` и публикация `APPROVE` проверены отдельными одноразовыми сценариями во временных проектах. Временные проекты удалены после выполнения.
- Выборочно прочитаны публичные переходы и их регрессионные тесты. Это не формальное доказательство отсутствия иных дефектов; живой запуск с иной моделью и OpenCode V2 не выполнялся.

## Дальнейшее развитие

[Стратегия развития](IMPLEMENTATION-STRATEGY.md) сохраняет неизменный цикл:
сильный supervisor планирует, поручает работу сменяемому pipeline,
сам проверяет и принимает решение, затем запускает следующий TODO или забег.
V-01/V-02 — ремонт переходов; V-03/V-04 — защита позиции supervisor;
V-05 относится к кодовым поручениям. План развивает память supervisor,
контракты стадий, handoff, ревизию состава активного run, создание новых
ролей в служебном run и упрощение интерфейсов awf.

Устаревшая папка аудита 25.09, её копия на рабочем столе, игнорируемые `.edtz` и созданные проверкой сборочные артефакты удалены. Исходные документы остаются в истории Git. Текущим отчётом следует считать только эту папку.
