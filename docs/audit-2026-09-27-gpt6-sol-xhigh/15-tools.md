# 15 — Избыточность и доступность tools

**Роль:** проектировщик интерфейса агентов. Проверены `registry.TOOLS`, `server.create_server`, описания обёрток и инструкции ролей.

Факт: 47 MCP tools (42 `awf_*`, 5 UI), без повторяющихся имён; сервер регистрирует весь список для каждого подключения. Единый реестр решил расхождение счётчиков A-08, но не уменьшил когнитивную нагрузку и не ограничил действия по роли. Открытый `U13` в `BACKLOG.md` верно описывает следующий шаг.

| Группа | Инструменты | Оценка |
|---|---|---|
| Обзор состояния | `awf_status`, `awf_run_status`, `awf_current_step`, `awf_brief`, `awf_load_supervisor_context` | Пять частично пересекающихся входов. Payload разный, но рекомендации «вызывать в начале» у `brief` и `current_step` конкурируют. Кандидат на один короткий и один подробный фасад после изучения вызовов. |
| Формы | `open_form` и две `awf_open_*_form` обёртки | Обёртки повторяют открытие, но задают шаблон/проект безопаснее; считать их полезными shortcut, а не удалять по одному сходству. |
| Запуск | `awf_start`, `awf_continue`, `awf_retry_stage`, `awf_run_next` | Разные переходы одного процесса; сейчас нужны, но их следует показывать только в подходящей фазе. |
| Recovery TODO | `awf_todo_remove`, `awf_todo_retire`, `awf_unblock`, `awf_restore` | Разные состояния и семантика; статический аудит не доказал мёртвость ни одного. |
| Опасные управления | `awf_approve`, `awf_reject`, `awf_reset`, `awf_rollback`, `awf_kill`, `awf_run_finish` | Присутствуют в общем реестре. Для worker/QA это лишняя поверхность ошибочного вызова. |

Оптимальная первая правка — **профили выдачи**, а не массовое удаление: supervisor получает управление забегом и решение; implementer — только нужный статус/передачу результата; QA — статус, tree-sha, prove-red и безопасные проверки без approve/reset/kill. Профиль должен тестироваться сравнением реально выдаваемого списка с разрешённым набором и учитывать версию агентного хоста. Для сокращения публичного API сначала собрать частоту использования и сценарии fallback; отсутствие упоминаний в шаблонах не доказывает отсутствия внешних пользователей.

Важно: скрытие MCP tools само по себе не создаёт жёсткой границы при разрешённом shell и общем файловом доступе. Для гарантии независимой приёмки нужны полномочия на уровне процесса/ядра; см. [16](16-supervisor.md).
