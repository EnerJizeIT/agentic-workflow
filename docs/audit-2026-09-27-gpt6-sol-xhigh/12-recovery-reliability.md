# 12 — Отказ, повтор и восстановление

**Роль:** инженер надёжности. **Проверка:** A-21 и новые исключительные исходы `run_next`.

**A-21 (исходный сценарий) закрыт:** при `StartResult(run_mode="noop"/"error")` `run_next` удаляет только созданный им `.ready`, освобождает резервацию, оставляет индекс на месте; предсуществующий сигнал сохраняет. Четыре сценария `test_audit25_a21_refused_signal.py` и весь адресный набор прошли.

**V-01 — P1 для foreground API, воспроизведено.** В `awf/api/pipeline.py:1079–1092` foreground запуск после исключения или ненулевого исхода возвращает `StartResult(run_mode="foreground", exit_code=1)`. В `awf/api/run.py:789–811` отказом считаются только режимы `noop/error`; далее `run_next` фиксирует `index + 1` и отвечает `started`. На временном проекте с подменой результата запуска получено: `outcome=started`, `index=1`, `current='TODO-0001'`, `.ready=True`. Пайплайн фактически завершился с ошибкой, а очередь уже считает элемент запущенным. MCP `awf_run_next` принудительно использует `background=True`; дефект относится к прямому API foreground пути.

**V-02 — P2, воспроизведено.** Вызов `start_pipeline` в `awf/api/run.py:779` не защищён `try/except/finally` для отката сигналов/резервации. На временном проекте при контролируемом `RuntimeError` получено: исключение наружу, `index=0`, `current='TODO-0001'`, `.ready=True`. Этот угол уже указан в `BACKLOG.md`, но пока не исправлен.

Временные проекты удалены сразу после сценариев. Тесты штатных возвратов не покрывают эти два исхода. Исправление должно задавать единое условие успешного запуска и откатывать только собственные побочные эффекты при любом отказе, включая исключение; после него нужны регрессии на public `run_next` и повтор вызова.

**Вывод:** штатный отказ A-21 исправлен; путь «ошибка вместо штатного результата» и foreground неуспех открыты.
